The static audit identified exactly nine default-stream dispatches: two in `quant.cu`, six existing paged-KV launches in `flashinfer.cu`, and the existing CUTLASS call in `gemm.cu`. The optional private build adds `at::cuda::getCurrentCUDAStream()` to those dispatches. It changes no arithmetic, quantization, tiling or attention implementation. It does not install over the original extension. The exact `current_stream_backend.patch`, build compiler/command log, and `stream_backend_manifest.json` distinguish this binary from P0. This is one adapter candidate, without configuration search.

Before any graph timing, the same Level-2 operator suite is run with original and patched binaries, recording the SHA256 of actual outputs and modified KV storage for every extension invocation. `stream_backend_equivalence.json` must pass. The pre-existing accumulator-narrowing failures are expected to remain failures; equivalence is not a claim that those cases are numerically valid. The full growing-cache graph verification must then pass for all three methods of a model. A passed panel uses the same patched binary for both eager and graph, 10 complete warmups and50 measured runs in each of3 balanced sessions. `raw_graph_runs/` keeps it separate from original-binary core measurements. Graph preparation, private-pool deltas, metadata updates, full prefix reconstruction and standalone inference peaks are accounted for explicitly.
